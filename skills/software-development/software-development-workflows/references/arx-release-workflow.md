# ARX release workflow

- Treat /srv/arx/app as production: it is a bind mount used by the arx container. Editing code there changes files immediately; server changes require container restart. Use an isolated git worktree for broad improvements, then merge only verified code; preserve live data JSON.
- Never serve the repository as a generic static directory. Explicitly allow app shell, required data endpoints behind authentication, and assets; reject dotfiles, source, deployment files and malformed URL encoding. Verify /.git/HEAD returns 404 via public HTTPS after deployment.
- Exercise security tests against a separate server port with no writes to personal data. For persistence/auth tests use temporary copies and identities. Existing DOM invariants alone do not validate authentication, proxy security or concurrent writes.
- If host Node prints PASS but aborts at shutdown, compare a trivial Node invocation and test in the deployed container runtime. Do not count a printed PASS with exit 134 as a passing command.
- When ARX proxies to Hermes dashboard auth, do not use Node `fetch` for requests that must satisfy Hermes Host validation: Fetch forbids overriding the `Host` header. Use `http.request` with `Host: 127.0.0.1:9119` and verify a fake login returns `401 Invalid credentials`, not `400 Invalid Host header`.
- Distinguish dashboard local-password authentication from Nous provider OAuth. Branding does not identify the credential authority; inspect the real login provider and form endpoint. Never ask for passwords through chat.
- With Codex workspace-write in a git worktree, avoid adding its parent directory via --add-dir: it can produce a conflicting synthetic .git mount and bwrap mkdir failure before every command. Remove the overlapping writable root, retain sandboxing, and verify /bin/true plus a repository read. Keep reports inside the worktree; let the parent commit if git metadata remains read-only. Exit code 0 from Codex does not prove implementation: inspect its final report and diff.
- For long implementation tasks use a durable background coding process with completion notification; record worktree, task brief, execution log and report paths. Verify actual execution starts and disclose what is deployed versus merely in progress.
